# E2 pilot 最終レポート（2026-09-28）


## Gold V1 最終試験（英語版、1回だけ実施、報告のみ）

E2 完了後、選定 checkpoint を固定したまま Gold V1（`gold_v1_adjudicated_en_mt.jsonl`、60 state・90 branch）で 1 回だけ評価した。結果は学習・選定・調整には使わない。

- 採点: 既存の `evaluation.run.score_quality`。Choice/Score は top-1、Noul は threshold accuracy。
- 入力: E2 と同じ chat 形式・順番平均（`e2/gold_eval.py`）。
- 本家 Jev は同じ Gold を API で評価した（21,920 入力トークン）。

| | Choice（n=40） | Score（n=30） | Noul（n=20） |
|---|---:|---:|---:|
| 学習前 Qwen3-4B | 0.975 | 0.733 | 0.850 |
| **選定 LoRA** | **0.950** | **0.733** | **0.800** |
| 本家 Jev 1.13 | 1.000 | 0.867 | 0.900 |
| 参考: 旧 pointer 最良（2026-09-25） | 0.525 | 0.367 | 0.650 |
| 参考: 人間どうし（2026-09-25） | 0.975 | 0.933 | 0.850 |

NLL（学習前 → 選定 LoRA / Jev）:

- Choice: 0.500 → 0.166 / 0.267
- Score: 4.100 → 1.044 / 0.313
- Noul: 2.686 → 0.885 / 0.254

- 1 問の重みは Choice 2.5pt、Score 3.3pt、Noul 5pt。選定 LoRA と学習前の top-1 の差は、どの kind も 1 問以内。
- 実用目安（Choice 0.90 / Score 0.80 / Noul 0.80）に対しては、Choice と Noul は届き、**Score（0.733）は届かない**。
- 本家 Jev との差は、Choice で 2 問、Score で 4 問、Noul で 2 問。Score の差が一番大きい。
- LoRA は確率の質（NLL）を大きく改善した。Choice の NLL は Jev より良い。ただし argmax の精度は学習前から上がっていない。

仕様: `internal-docs/E2_PILOT_SPEC.md`。E2 のデータ作成・学習・選定の間、Gold V1 は一切読んでいない。Gold V1 は E2 完了後の上記 1 回だけ使った。

## 結論

**E2 は不合格。** 教師テストの全体 top-1 は学習前より +3.75pt（95% CI [+2.08, +5.50]）で、事前に決めた合格基準 +5pt に届かなかった。§7.2 の条件 2〜5 はすべて満たした。

| 条件（§7.2） | 結果 | 判定 |
|---|---|---|
| 1. 全体 top-1 が +5pt 以上 | +3.75pt | **未達** |
| 2. 全体の Brier・NLL がどちらも下がる | Brier −0.0295、NLL −1.047 | 達成 |
| 3. kind 別に明確な悪化がない | 全 kind・全指標で改善側 | 達成 |
| 4. 全体 top-1・Brier・NLL の bootstrap 95% CI が 0 をまたがない | 3 指標とも 0 をまたがない | 達成 |
| 5. 人間テストで明確な悪化がない | 悪化した指標なし | 達成 |

基準の +5pt は厳しすぎた可能性がある。仕様 §12 では学習前から「厳しい可能性がある」と書いていた。事後の参考値として、本家 Jev 1.13 でも学習前からの改善は +4.4pt 相当だった。ただし結果を見た後で基準は動かしていない。基準の見直しは E3 の開始前に行う。

## 設定

- backbone: `Qwen/Qwen3-4B-Instruct-2507`、bf16、SDPA。
- 学習: LoRA（r=16、α=32、dropout 0.05、all-linear、`lm_head` は対象外）。
  - 損失: 答え位置の許可記号 K 個に対する KL(q‖p)。
  - 1 step あたり 16 行（64 branch）、AdamW、warmup 3% の後は一定の学習率。
  - 毎行、選択肢の順番をランダムに入れ替えた（Choice/Score は全順列から、Noul は 50% で反転）。
- 入力: 公式 chat template で、state を共有 prefix にして branch を tree mask で pack した（`e2/chat_packer.py`）。
  - 単独入力との一致試験（§5.4）: 学習形式 64 branch、評価形式 64 branch とも material flip 0。
- 教師: `deepseek-flash`、non-thinking、temperature 1、top-20 logprobs。
- 評価: Choice/Score は 4 順番、Noul は 2 順番で予測し、正準順に戻して平均した。
- 実行環境: A100 SXM 80GB、torch 2.8.0、transformers 5.17.0、peft 0.21.0。学習前と学習後は同じ環境・同じコードで測った。

## 学習曲線と checkpoint 選定（val のみ）

学習率 3 通り × 最大 3 epoch で、1/4 epoch ごとに val を評価した。早期終了はどの run でも発動しなかった。

| lr | e1 末 NLL | e2 末 NLL | e3 Q1 / Q2 / Q3 / Q4 | 最良 |
|---|---:|---:|---|---:|
| 5e-5 | 0.368 | 0.355 | 0.351 / 0.365 / **0.345** / 0.355 | 0.3447 |
| 1e-4 | 0.362 | 0.358 | 0.354 / 0.367 / **0.345** / 0.361 | 0.3453 |
| 2e-4 | 0.363 | 0.354 | 0.367 / 0.376 / 0.387 / 0.368 | 0.3537 |

- 選定: **`lr=1e-4`、epoch 3、quarter 3**。
  - val NLL 最小は 5e-5（0.3447）だったが、1e-4 との差は 0.00054。0.001 未満なので、Brier が小さい 1e-4（0.0361 vs 0.0380）を選んだ。
- val NLL は epoch 2 で頭打ちで、1/4 epoch ごとの揺れ（約 0.01〜0.02）のほうが epoch 間の改善より大きい。val top-1 は epoch 1 の途中から 0.85〜0.866 で横ばい。
- 2e-4 は epoch 3 で val NLL が悪化した（train KL は 0.358 → 0.157 → 0.086）。過学習の兆候。
- epoch を増やしても改善は見込めない。上限はデータの量と多様性で決まっていると考えられる。

## 本家 Jev との比較（参考、合否には使わない）

- 本家 Jev の評価条件: `jev-1.13.0` を API で呼んだ（1 state = 1 call、設問はまとめて送信）。記号ラベルを使わないので、順番平均はせず正準順の 1 回だけ。
- 費用: eval 全体で 494,060 入力トークン、$0.021。
- **教師テスト**: 選定 LoRA は top-1 で −0.66pt、NLL は同じ、Brier・ECE は Jev が良い。教師を真似て学習した LoRA に有利な指標であることに注意。
- **人間テスト**:
  - argmax 一致は Jev が +2.5pt 上（0.928 vs 0.903）。
  - NLL は選定 LoRA が人間の回答分布に近い（0.299 vs 0.372）。
- **公式ドキュメントの例 20 問**（今の Jev との一致度）:
  - argmax 一致: 学習前 15/20、選定 LoRA 18/20。
  - 平均 TVD: 0.180 → 0.125。
  - severity 表の Kendall τ: 学習前・選定 LoRA とも 1.0。
  - ドキュメントの掲載値は、今の Jev とも一致しない（古いバージョンの出力と考えられる）ので、基準には今の Jev を使った。

## 限界

- 教師テストの指標は「教師にどれだけ近いか」であって、正解率ではない。
- 人間との一致は、教師（0.939）が上限の目安になる。蒸留を続けても、Jev（0.928）を超える余地は小さい。
- val は 125 state・500 branch と小さく、checkpoint 選定の差（NLL 0.0005）は評価のばらつきより小さい。
- eval 1,200 branch と人間テスト 400 case は、この比較に使った。今後の学習の選定には使えない。

## 次（E3 に向けて。開始前に基準を固定する）

1. 学習タイプを増やす（180 → 500〜1,000）。
2. タイプと state のドメインのずれを直す（fallback を廃止するか、ドメインに合わせる）。
3. Score を重点的に扱う（全モデルで一番弱い kind）。
4. 新しい eval と人間テストを作る。合格基準は「教師との差を何割埋めたか」のような形で、学習前に決める。
